# Устройство

```
Telegram-канал ──► Telethon (аккаунт копировщика) ──► parser.py ──► main.py ──► trader.py
                                                                       │            │
                                     бот ◄── отчёты/команды ───────────┘            ▼
                                     группа «FxCopier — сделки»            mt5link.py ──RPyC──► bridge_server.py
                                                                                              (Windows-Python под Wine)
                                                                                                     │ MetaTrader5 lib
                                                                                                     ▼
                                                                                         terminal64.exe (FxPro MT5, Wine)
                                                                                                     │
                                                                                                     ▼
                                                                                            серверы FxPro (Лондон)
```

## Файлы

| Файл | Что делает |
|---|---|
| `parser.py` | Разбор сигналов (`parse_signal`) и команд канала (`parse_command`). Без зависимостей — тестируется где угодно |
| `trader.py` | Лот по таблице, решение о входе (`decide_entry`), план сделки (`prepare`) и исполнение (`execute`), риск в деньгах, безубыток, перенос SL/TP, закрытия |
| `guard.py` | Второй слой защиты: пороги риска, проверка сделки и состояния счёта |
| `mt5link.py` | Доступ к MT5: на Windows — библиотека напрямую, на Linux — через RPyC-мост |
| `bridge_server.py` | RPyC-сервер, запускается Windows-Python'ом под Wine (служба `fx-bridge`) |
| `main.py` | Telegram-клиент, обработка сообщений, мониторинг позиций (каждые 0.5 с), отчёты, команды |
| `tg_login.py` | Вход в Telegram по QR (`fxctl tg`) |
| `setup_bot.py` | Создание бота через @BotFather и группы (`fxctl bot`) |
| `test_trade.py` | Проверка связки на демо без Telegram (`fxctl test`) |
| `list_chats.py` | Список каналов аккаунта |
| `deploy/install.sh` | Установка на чистый Ubuntu |
| `deploy/fxctl` | Команда управления на сервере |
| `deploy/run_mt5.sh` | Обёртка запуска терминала для systemd |
| `config.example.yaml` | Все настройки с комментариями → копируется в `config.yaml` |
| `tests/` | Тесты: `python tests/test_core.py`; `fake_mt5.py` — имитация брокера |

## Службы (systemd, пользователь `fx`)

| Служба | Что |
|---|---|
| `fx-xvfb` | Виртуальный экран `:99` для Wine |
| `fx-mt5` | Терминал MT5 (`run_mt5.sh` + `/portable /config:C:\fx\start.ini` — логин/пароль/сервер и разрешение алготорговли) |
| `fx-bridge` | Мост RPyC на `127.0.0.1:18812`. `PartOf=fx-mt5` — перезапускается вместе с терминалом |
| `fx-copier` | Сам копировщик (`venv/bin/python main.py`) |

## Логика торговли

**Приоритет правил (решение владельца 05.10.2026): 1) команды и данные канала → 2) правила куратора →
3) защита владельца (guard).** Своих торговых правил сверх этого копировщик не добавляет.
Правила куратора (из переписки): 3 одинаковые позиции на TP1/TP2/TP3, лот по таблице, после TP1 стоп в
безубыток «с запасом», вход только на точке входа (допуск $2), не входить если тейки прошли,
не более 2 сигналов одновременно, без команды канала не закрывать, команды канала выполнять.

- **Сигнал → 3 позиции** (TP1, TP2, TP3) с общим SL. Общий лот — по таблице куратора от баланса
  (`lot_table`), делится на 3, округляется вниз. Если на 3 не хватает — 2 позиции (TP1, TP3) или 1 (TP2).
- «Большой/длинный стоп, занижаем лот» и пометка RISKY → лот ÷2. Если канал пишет это **отдельным
  сообщением** после сигнала (обычно через 20–60 с, когда мы уже вошли) — в течение 15 мин уменьшаем
  открытое вдвое (`reduce_half`: из 3×0.01 закрываем среднюю позицию TP2; из 3×0.02 — по 0.01 с каждой).
- **Вход** (`decide_entry`, решение владельца 05.10): диапазон из сигнала («4158-4155») — **диапазон открытия**,
  вне его не открываем. Точка входа E внутри диапазона — настройка `risk.entry_level` (0 = лучший край:
  у BUY нижний, у SELL верхний; 1 = худший; сейчас 0.5 — середина). Владелец меняет её в группе
  командой **`/entry 30`** (обе стороны) или отдельно **`/entry buy 20`**, **`/entry sell 80`**
  (`entry_level_buy` / `entry_level_sell`; хранится в state.json, важнее config.yaml); видна в `/status` и при запуске.
  Цена в диапазоне и не хуже E → по рынку. Хуже E (в диапазоне или за ним к тейкам) → BUY LIMIT / SELL LIMIT
  по E (ждёт до 4 ч, `pending_expiry_min`; снимается, если цена дошла до TP1 или стопа без нас).
  Цена лучше диапазона (BUY — ниже, SELL — выше, но не вплотную к стопу) → все позиции сразу по рынку
  (`below_range: market`, правило куратора 06.10, включено владельцем; `skip` — пропуск, `stop` — STOP-ордер на крае).
  Одна цена в сигнале («4075») → диапазон цена ± `entry_tolerance` ($2). LIMIT-сигналы — так же, ждут до 7 дней.
- **Цена уже прошла TP1, когда пришёл сигнал** (`after_tp1: rest_limit`, решение 06.10): позиции на TP2/TP3 —
  по рынку (если цена до них не дошла), позиция TP1 — лимиткой на точку входа. Безубыток — при касании TP2
  (`rec.be_k`). Если канал сдвигает тейк у пропущенного сигнала («Отодвигаю первый TP на 4190»)
  в течение 10 мин — вход пересматривается (`retry_skipped_on_tp_change`).
- Другие режимы входа (`entry_mode`, сравнение 06.10 на истории 27.05–02.10, старт $1000, комиссия $8/лот):
  `limit` BUY20/SELL80 — $1254 (основной); `ladder` — лесенка, своя точка у каждой позиции — $1042…1172;
  `pullback` — лимитка подтягивается за ценой, вход на откате $1–3 — $822…881 (входит в основном, когда цена
  разворачивается против нас); запасной вход по рынку через N мин (`entry_fallback_min`) — $1109 (5 мин),
  $1223 (15 мин); `curator` — правила куратора 06.10 (у диапазона ±$1 или лучше — 3 по рынку, хуже — TP2/TP3
  по рынку, БУ при TP1) — $1015; `market` — $967; `split` — $996…1091.
  Цена лучше диапазона (`below_range`): пропуск — $1254, `market` (куратор: «ниже — можно на все три, если
  с публикации не было ни тейка, ни стопа») — $1304, `stop` — $1199. Цена хуже диапазона (`above_range: rest`,
  куратор: 2 позиции на TP2/TP3 по рынку) — $1227 против лимитки. Позиции на TP2/TP3 чаще всего уходят
  в безубыток, поэтому для них цена входа важнее всего.
- **Проверка «оставить лимитки после TP1» и «входить по рынку, если цена убежала» (07.10, сигнал #1338)**: в #1338
  SELL 4113–4119, цена на момент сигнала 4112.86 (на $0.14 ниже диапазона), лимитки стояли на 4114.2, цена ушла
  к TP3 и не вернулась — лимитки не исполнились бы никогда, снятие ничего не стоило. Вход по рынку дал бы ≈ +$24…28
  (лот 0.01×3). Упрощённая проверка на 242 сигналах золота с мая (`tools/sim_variants.py`, лот 0.01×3, без команд
  канала; важны только отличия вариантов, не абсолютные цифры): текущие правила −22; держать лимитки TP2/TP3 после
  TP1 −127; по рынку при цене до $1 за краем −114; всегда по рынку −44; TP2/TP3 по рынку −69. Вывод: правило не менять.
  Осторожно: среди сигналов, где цена дошла до TP1 без нас, вход по рынку «выигрывает» всегда — но это знание задним числом.
- `sl_rule` (по умолчанию `none`) — стоп ближе, чем в сигнале, или пропуск сигналов с дальним стопом. Проверено 07.10:
  все варианты хуже стопа канала ($1040…1277 против $1304); у канала сигналы с дальним стопом самые надёжные.
- Вход после TP1 при половинном лоте (позиции TP1 и TP3): безубыток — когда цена дойдёт до TP2 канала (раньше ждал TP3).
- Если часть позиций уже вошла (лесенка, split), а цена дошла до TP1 — неисполненные ордера снимаются.
  Итог сигнала, где часть позиций отработала, а лимитки сняты, теперь попадает в журнал и отчёты.
- **Безубыток**: цена коснулась TP1 → SL оставшихся позиций = вход ± `be_offset` ($0.3). Если цена уже
  у входа — закрываем по рынку. Канал пишет «стоп в БУ пока не переставляю» → возвращаем исходный стоп
  и больше сами в БУ этот сигнал не переводим (ждём команды канала).
- **Вопросы владельцу кнопками** (07.10): сигнал пришёл позже 2 мин (если с публикации цена касалась TP1 или
  стопа — пропуск, условие куратора) и покупка с длинным стопом («занижаем риск»/RISKY: на истории 7 из 14 в минус,
  −$106) → сообщение «✅ Входить / ❌ Пропустить», ждём 15 мин, без ответа — пропуск; остальные сигналы не ждут.
- **Цена уже прошла TP1** (`after_tp1: rest`, 07.10, по ответу куратора): 2 позиции на TP2 и TP3 по рынку, без TP1.
- **Страховка от пропусков**: кроме событий Telegram, копировщик раз в 20 с (и сразу при старте) читает
  новые сообщения канала и обрабатывает непрочитанные (`state.last_msg_id`, `seen_ids`). 05.10 сигнал #1317
  пришёл во время 3-минутного перезапуска и Telegram его не дослал — теперь такие догоняются. Догнанный
  сигнал старше 2 мин исполняется, только если ему ≤ 4 ч и цена с момента сигнала не касалась TP1 и стопа
  (`late_signal_problem`, минутные свечи MT5).
- **Команды канала** — см. SIGNALS.md. Команда без reply применяется к последнему активному сигналу.
- **Риск-лимиты**: ≤2 активных сигнала (куратор); сигнал старше 120 с не исполняется (сбой связи).
  Дневной лимит убытка и закрытие в пятницу выключены (`max_daily_loss_pct: 0`, `weekend.enabled: false`):
  у куратора их нет, а на истории 06–09.2026 дневной лимит отрезал прибыльные сигналы после утренних стопов.
- **Второй слой защиты** (`guard.py`) — проверка плана сделки по реальным цифрам счёта перед отправкой ордера.
  Опасно, если: риск при стопе > 10% баланса; вместе с открытыми > 15%; стоп дальше $80 (золото);
  лот > 2× табличного или > 0.5; маржа > 50% свободных; 5-й сигнал за 30 мин. Тогда ордер не отправляется,
  новые сигналы на паузе, в группу — кнопки «✅ Открыть как есть / ⚖️ С безопасным лотом (риск ≤10%) / ❌ Пропустить».
  Разрешение действует 15 мин; без ответа сделка отменяется, пауза остаётся до «▶️ Продолжить».
  По счёту: 3 убытка подряд или просадка 25% от пика → пауза и кнопки «Продолжить / Оставить на паузе».
  Команда канала отодвинуть стоп дальше от входа → кнопки «Перенести / Оставить».
  Без бота — те же решения командами `/approve`, `/approve_safe`, `/reject`, `/resume`, `/slok`, `/slno`.
  На истории канала (4 мес.): 20 срабатываний (≈1 в неделю), в основном сигналы с длинным стопом.
- **Защита режимов**: `demo` откажется работать на реальном счёте; `live` требует `i_understand_live_trading`.
- Свои позиции копировщик узнаёт по `magic` (770077) + тикетам из `state.json` + комментарию `WW<id>-<k>`.
  Ручные сделки не трогает.

## Отчёты

`journal.jsonl` — по строке на каждый закрытый сигнал (итог из истории сделок MT5).
Отчёты строятся из `state.json` (все сигналы и причины пропуска) + журнала:
день (Пн–Пт 23:50), неделя (Пт 23:52), месяц (1-е число 10:00), `/report [week|month]`.

## Windows вместо Linux

Код тот же: на Windows `mt5link.py` использует библиотеку `MetaTrader5` напрямую, мост и Wine не нужны.
Поставить MT5 FxPro + Python 3.11, `pip install -r requirements.txt`, заполнить `config.yaml`
(`terminal_path` — путь к terminal64.exe), запустить `python tg_login.py`, затем `python main.py`
(автозапуск — Планировщик заданий).
